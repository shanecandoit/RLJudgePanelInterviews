03 / Mechanism map

The panel is a chain of components, not one intervention.

1. Collect truthReal trajectories and oracle queries supply verified transitions. No model can prioritize a successful interaction it has never seen unless exploration reaches it.
2. Fit the panelBootstrapped dynamics/reward/termination models learn from real data; anchor errors determine competence weights.
3. Spend samplesDisagreement selects candidate state/action queries, mixed with random anchors. One judge has no ensemble variance.
4. Improve behaviorPPO learns from rollout batches; DQN learns from real replay; Dyna adds model-generated transitions. Real evaluation checks the result.

A method can fail at any link: insufficient exploration, shared blind spots, a poor query score, invalid imagined states, misleading reward predictions, or an optimizer exploiting those predictions. Better average prediction error does not automatically mean better decisions.

Most plausible failure mechanisms to test—not established causes

  • Invalid imagined states: current models regress numeric encodings of categorical grid objects. Panel PPO averages next-state predictions and feeds the result back into the policy. A numerical average can be an impossible grid. Dyna samples a judge instead of averaging, but that judge still predicts continuous grids.
  • Reward optimism: panel PPO clips imagined reward to [0,1]. Around true zero reward, positive prediction errors survive while negative errors are removed. Measure whether this creates exploitable reward. Dyna’s imagined reward uses [-1,1], so cross-algorithm model handling is not identical.
  • Shared errors: bootstrapped judges can agree and still be wrong. Disagreement can miss a common blind spot; scalar error correlation is only a diagnostic, not a causal test of diversity.
  • Model exploitation and long rollouts: the policy can visit prediction errors outside training support. Short rollouts and real updates may help, but the historical sweep does not prove that either is sufficient.

Where the proposed error specialist fits

Score the existing panel on newly verified transitions before training on them. Bin mistakes by movement, turning, pickup, door interaction, reward, and termination; train a candidate on a mixture of ordinary examples and those errors. Validate on separate real transitions. Admit the candidate only when the combined panel improves, including on the events that matter for reward.

Compare a specialist against both “four judges trained longer” and “five ordinary judges.” A global average may dilute a specialist, so its routing or correction rule also needs validation. Deliberate specialization changes the meaning of disagreement; do not treat specialist disagreement as automatically calibrated uncertainty.

A practical cap: stop adding judges when several candidate seeds fail to improve held-out panel predictions and retained policy return enough to justify compute. That is a stopping rule for a particular architecture, dataset, and budget—not a universal maximum number of judges.

05 / Decision protocol

Define the answer before picking a winner.

Preserve the original claim. Report its first-crossing sample ratio separately. Do not change H1 to match whichever configuration wins. Add retained performance as a declared robustness requirement for the next confirmation experiment.

  1. Freeze tasks, settings, and budgets. Keep Empty 5×5 as a positive control and LavaGap/DoorKey as harder tests. Select a candidate using exploratory data, then use fresh training seeds and fresh final-evaluation layouts. These three tasks can support a bounded MiniGrid claim, not the whole planned Procgen/generalization scope.
  2. Establish a learned reference. For each task, estimate PPO’s late return across independent seeds and inspect whether it has stabilized. A final-20% average is a proxy. If the baseline has not learned, H1 is not measurable on that task; do not substitute a random-search peak for a confirmatory threshold.
  3. Use one target for all methods. Let T = 0.8 × the frozen PPO reference. Report the original first crossing. Proposed retained crossing: first of five consecutive evaluations at or above T, followed by a final-20%-of-samples mean at or above T. Five checks are an operational rule, not a statistical proof; pick a common evaluation interval before running confirmation.
  4. Retain non-reaching seeds. Treat their crossing times as right-censored/infinite for the median; show reached/attempted and the full per-seed data. Never calculate the headline median using only successful runs. Report uncertainty from independent training seeds, not from checkpoints treated as independent samples.
  5. Compute the two required ratios. PPO samples / panel samples ≥5, and Plan2Explore samples / panel samples ≥2, at the same target. Require the retained-performance result alongside the original first-crossing result. If a comparator or panel never reaches the target, report censoring instead of a fabricated finite speedup.
  6. Separate mechanism and cost claims. Run same-J disagreement-versus-uniform acquisition and equal-policy-update DQN/Dyna controls. Report real samples, evaluation samples, model/policy updates, training time, full elapsed time, and eventually FLOPs.
Current reporting status: the sustained rule above is a proposal, not a retroactive pass/fail label. The tables use the existing first-crossing definition and explicitly labeled late-average diagnostics. No completed experiment yet meets the full confirmation protocol.

Interpretation rules

  • Works only on Empty: report a restricted navigation result; the broad H1 remains unsupported.
  • DQN alone matches the gain: replay is a sufficient alternative explanation until the panel beats it.
  • Dyna helps but disagreement does not: support a model-assisted learning result; do not attribute it to judge-guided querying.
  • First crossing improves but late return collapses: report a transient efficiency effect, not reliable learning.
  • Several judges help at matched samples but not matched compute: report the explicit compute-for-samples tradeoff.
